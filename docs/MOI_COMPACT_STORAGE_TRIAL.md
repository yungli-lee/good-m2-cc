# 實價資料精簡儲存試驗 — 2026-10-30

## 使用者範圍

維持現有容量。所有資料庫欄位及前台 layout 保留；不再重複寫入前台不需要的原始欄位內容，完整官方來源另存。這一階段先離線量測，不刪改既有資料，也不恢復自動回補。

## 查詢資料保留方式

| 資料 | 試驗處理 |
| --- | --- |
| 主檔所有標準化欄位 | 全部原樣保留，包含地址、日期、金額、面積、屋齡、樓層與來源鍵 |
| 主檔 raw_record 欄位 | 欄位保留；僅保存官方「備註」原文、精簡版本及原始 ZIP SHA256 |
| 土地／建物／車位所有標準化明細 | 全部原樣保留，包含持分、車位價格為0、所在樓層、地段地號 |
| 明細 raw_record 欄位 | 欄位保留；一般列為空物件，異常持分列保留官方分子／分母原值 |
| 官方主檔／明細指紋及明細來源列定位 | 原樣保留，不能改成精簡JSON的指紋 |
| 官方完整原始 CSV | 留在逐位元相同的原始 ZIP；未完成可還原的長期備份驗證前，不可精簡既有 DB |

目前兩個公開API只依賴 raw_record 的「備註」及異常持分原文；其餘顯示、篩選及同物件歷史比對使用標準化欄位。本試驗沒有修改API或元件，因此layout沒有變更。建物屋齡須先由完整來源解析，再做精簡投影。

## 實測

113S2原始ZIP SHA256：`e247d0f20365b790685b5e63a2197d40200e0f436ceb14f3ee88e16ecd095972`。完整63份主來源檔、180,310筆交易、616,679筆明細測量：JSON payload 695,392,664 bytes → 360,335,437 bytes，減少48.18%。每個標準化欄位及指紋逐筆比對一致；官方備註及異常持分另逐筆比對。來源唯一異常仍為官方持分7/5，原文保留、標準化持分null。

DB只讀抽樣：10,000主檔的整列JSONB平均2,190 → 1,214 bytes；13,368明細平均851 → 551 bytes。這是JSON表示大小，**不是實際釋放磁碟量**，不能乘目前總磁碟直接宣稱可回收，也不能據此保證47個未匯入季度可放入7GB。現有索引、頁面空間、TOAST壓縮、重複版本、WAL及未來更新仍須計入。

目前主檔含索引約2.97GB、明細含索引約3.16GB；上述查詢均為只讀，既有資料庫未縮小。

## 啟用前的必要工作

1. 為每個已匯入季度與當期保存完整ZIP、SHA256、報告與來源對照表；備份必須可長期取回。Actions的7天artifact不是長期備份。驗證重新下載後SHA相符。
2. 逐來源建立可還原定位：ZIP SHA、來源檔名、官方交易編號／明細來源列、原始指紋。不能只有一個總ZIP而無法回找來源。
3. 新匯入需有不同的chunk版本，保留舊批次紀錄；不能拿舊chunk SHA冒充已完成精簡，也不能因模式轉換讓舊期覆蓋新期。
4. 先做有大小上限的staging小批試驗，核對前台API輸出、筆數、備註、持分、車位、歷史比對與實際資料表大小，再決定是否擴大。
5. 已有資料精簡需逐列證明長期備份可還原，再分批進行；UPDATE不等於立即釋放磁碟，重寫表／VACUUM FULL可能需要額外空間及鎖，不可在近上限時盲目執行。

7GB安全停止線、暫停的回補工作、Production及付費配額均保持原狀。此試驗沒有宣稱全國資料已補足，也沒有宣稱已取得實際磁碟節省量。
